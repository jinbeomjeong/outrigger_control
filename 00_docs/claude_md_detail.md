## 2. SCM(S9) Chrono 실행 규칙 원문

SCM(S9) Chrono 실행 규칙(2026-11-08 실측): `--threads`가 다르면 결과 비트가 다르므로 스레드 수는 실행 조건으로 고정·기록한다. P코어 우선(SCM 실측 E 약 1.5배 느림, 11-08; L1 Chrono는 2.4~2.5배, S0), `OMP_WAIT_POLICY=PASSIVE`를 시작 전 env에 둔다(비트 동일). Chrono·SCM은 GPU 이득이 없고 CRM(FSI-SPH)은 쓰지 않는다. 시간의 약 3/4은 SCM 내부(볼록 껍질·광선·flood fill), 1/4은 Python 콜백이다. 볼록 껍질 훅 기본 **fast**(2026-11-09 채택, G-D P 단독 1.30배·G-C npz 비트 동일): `OUTRIGGER_HULL_HOOK` 미설정 = fast, `=off`로 되돌린다. DLL `03_src/outrigger_sim/native/chrono_hull/bin/chrono_hull_hook.dll`은 git 제외라 새 checkout·worktree에는 복사하거나 `build.ps1`로 빌드한다(없으면 경고 뒤 off, result.json `hull_hook.fallback_reason`). pychrono를 갱신하면 `hash_mismatch`로 off가 되므로 G-A를 다시 한다. 기록: result.json `hull_hook`, batch.json `hull_hook_requested`·`hull_hook_effective`(섞이면 `MIXED_HULL_MODE`). DLL은 검증 빌드 SHA-256 `cec997d7…`로 고정한다(`hull_hook.VALIDATED_DLL_SHA256`). 다르면 기본은 off 폴백(`dll_sha_unvalidated`), 명시 모드는 exit 2이고, 새 빌드를 검증할 때만 `OUTRIGGER_HULL_HOOK_ALLOW_UNVALIDATED=1`을 쓴다. `s9_batch --resume`은 훅 요청이 다르면 멈춘다(`--allow-mixed-hull`).
