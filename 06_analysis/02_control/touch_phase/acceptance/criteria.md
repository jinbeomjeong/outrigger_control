# C4G2·K1 인수 하네스 합격 기준

작성: control-expert, 2026-11-04, **본 실행 전**. 이 파일의 기준은 결과를 본 뒤 바꾸지 않는다. 바꿔야 하면 이 파일을 고치지 않고 사용자 결정으로 새 파일에 적는다.

## 공통

- 코드: 고정 체크아웃 `scratchpad\cad_c4g2\wt`, 커밋 74032be. 프리셋은 `C2Config().with_10hz_d1(touch_twist_hold=True, reapproach_retrigger_two_samples=True)`와 같게 `acc_common.py`가 기본값으로 넣는다. `03_src`·YAML·명세는 고치지 않는다.
- 재생기: 이 묶음의 판정 스크립트(`r67`, `r69`, `s9_soil_event_screen`, `s9_slope_fix_candidates`, `s9_soil_slope`, `r72`, `r79_*`, D8·크롤러 구동기)는 `contact_replay`를 쓰지 않는다(grep 2026-11-04: `verify/s8_control.py`, `verify/contact_metrics.py`, `05_ml`만 사용). 그래서 74032be로 시작하고 ce21ffa 체크아웃은 쓰지 않는다. `c2.py`는 두 커밋이 같다.
- 모든 묶음: 오류 행 0, `main_tree_modules` 0, 기록된 `c2_sha256`이 체크아웃과 같고 조합 설정이 맞을 것. 하나라도 어기면 그 묶음은 판정하지 않고 다시 돌린다.
- 판정 단위와 라벨: 행 통과·실패는 각 스크립트의 기존 판정을 그대로 쓴다. 조건은 강체·연약 하네스뿐이고 Chrono가 아니다.

## 앞선 판정의 열린 항목 처리

`c4g2_k1_judgement.json`의 K1 `open`(재생기 K1 미반영)은 `chrono/c4g2_k1_replay_rejudge.json`(ce21ffa)으로 처리했다.
- K1 5행 J_C 놓침 0, 재생 시작 시각이 기록과 일치. J_P 놓침은 `sampling_only` 3건이다.
- 그러므로 Chrono K1 행의 "놓침" 기준은 충족으로 읽는다. 항목 9의 M2·M4 값은 재판정 값을 쓴다.
- 표시 행 C-S8-41 FLAG와 R15 "재접촉 ≤ 2.5 s" 표시는 재생기와 무관하게 남는다. 사용자 결정이 없는 한 어긋남으로 계속 적는다. 이 인수에서 합격 조건으로 쓰지 않고 기록한다.

## 잡음 판정 (명세 423.1, 429.11.2와 같은 방식)

- 단위: S1 전방(`S1@FL`, `S1@FR`, 판정 밖)을 뺀 L2 실행의 실패율. 실패 = S-1~S-6 중 하나라도 실패. 판정은 체크아웃의 `r79_sensor_judge.judge_results`이고 참조는 이 묶음이 새로 돌린 같은 조합의 L1이다.
- **합격: 단측 Clopper–Pearson 95 % 상계 ≤ 3 %.** n = 855에서 실패 17건 이하다(k = 17 통과, k = 18이면 3.106 %). 계산 경로 둘(`beta.ppf`, `binom.cdf` 근).
- 함께 볼 조건: L1 거짓 LOC 0, unmatched 0, errors 0, SGS `controller_settings` 불일치 0.
- 기준값 대조(판정 아님): 현행 11/855 = 1.29 %, CP 2.12 %. 통과→실패 행은 목록으로 적는다.
- L3은 n = 501에서 8건 이하가 3 % 상계이지만, Q-F(429.11.3)가 이미 normal 등급으로 좁혀져 있어 합격 조건이 아니다.

**미달 시 처리(사용자 결정):** 원인 분석과 후보 안까지만 한다. 재설계·코드 변경은 하지 않고 멈춰서 묻는다.

## 후보별 분리 처리

미리 분리 실행하지 않는다. C4G2가 작동하면 `INFO_TOUCH_TWIST_HOLD` 또는 G2 공통 비율이 남고, K1이 작동하면 `leg_reapproach_deferred:*:retrigger`가 남으며, 둘 다 없으면 명령 해시가 끔과 같아야 한다. 실패 행이 나오면 그 키만 `ACC_COMBO=c4g2`, `k1`, `off`로 다시 돌려 가른다(`--keys`, `R67_FILTER`, `R426A_FILTER`). 이 재실행은 원인 분석이고 합격 수를 바꾸지 않는다.

## K1 토양 Chrono 행 선정 (사용자 승인, 자동 시작)

토양 하네스 합격(위 표) 때만 시작한다. 실패가 있으면 시작하지 않고 묻는다.

순서대로 2~3건을 고른다. 표는 `acc_judge.py`가 `soil_chrono_pick`으로 낸다.
1. 후보: `two` 판독, G1·J2, 빠른 사건(RE1bF, FS24), timing level. K1이 작동한 행(재접근 시작 ≥ 2회이고 끔과 명령 해시 다름).
2. 순위: 인접 다리 창 안 최소 힘이 낮은 순. 동률은 사건 다리 부상 합이 큰 순, 그다음 키 이름 순.
3. 첫 행은 순위 1. 둘째 행은 첫 행과 다른 토양에서 순위가 가장 높은 행. 셋째 행은 앞 두 행과 다른 $F_s$ 또는 다른 사건 다리에서 순위가 가장 높은 행이고, 없으면 2건으로 끝낸다.
4. 후보가 2건 미만이면 Chrono를 시작하지 않고 묻는다.

Chrono 행의 판정은 `chrono/c4g2_k1_judgement.md`의 사전 기준(판정 행 실패 0, 새 FLAG·놓침 0, 대상 행 최소 힘 개선, 다른 다리 F_min 여유 유지, READY 증가 P3-6 안)을 그대로 쓴다. 토양 사건 Chrono는 저장 끔 짝이 없으므로 같은 코드 끔 짝이 필요한지는 시작 전에 비용과 함께 적는다.
