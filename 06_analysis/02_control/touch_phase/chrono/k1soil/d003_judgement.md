# G1 FLFs0 δ 0.03 끔 대 C4G2 단독 Chrono 판정

대상: `S9EV_G1_FLFs0_RE1bF_d003_{off,C4G2}`, G1, 패드 B, 상단, F_s 0, RE1bF(30 mm/0.05 s), 사건 36.33 s, 유량 끔, 코드 74032be. 음되먹임, $T_s$ 0.1 s, $d$ = 1. 저장 기록 분석이고 새 시뮬레이션은 없다. 수치 `d003_values.json`, `d003off_values.json`, `d003_ma.json`.

## 결론

- **C4G2 탓이 아니라 현행 제어기의 기존 약점이다.** 끔과 C4G2 단독이 함께 E-3 실패이고, 짝 차이는 여유 +0.17 kN으로 C4G2가 약간 낫다.
- **약점의 내용:** 사건 뒤 재접근이 FL·RR을 번갈아 밀 때 RL 로드 축력이 짧게 F_min 아래로 내려간다(55 ms). 패드 부상은 없고 0.5 s 이동 평균은 F_min보다 36.5 kN 위다.
- **판정 규칙에 따라 읽기가 갈린다.** 하네스 판정 E-3(1 ms)은 실패, v4 표 5 주의 빠른 사건 규칙(0.5 s 평균, 부상 없음)은 통과다.
- **v4와의 충돌:** "통과" 자체보다 "G1 ≥ 29.86 kN", "토양 강성이 사건을 완만하게", "Chrono 짝 없음"이 문제다. 같은 제어기 Chrono에서 7.14~21.52 kN이다. 문구안은 아래에 있다.
- **권고:** C4G2 병합을 막을 이유는 이 행에 없다. v4 수정 여부는 사용자 결정이다.

**추정**
- 짝 차이 0.17 kN은 보류가 만든 작은 상태 차의 몫이고 위상·토양 산포보다 훨씬 작다. 기록상 이득으로 읽지 않는다.

Chrono 위상은 2개뿐이다. δ 0.03이 최악이라는 근거는 없다.

## 3. 보정 추정과 하네스

| 값 (RL 기준, kN) | 계산 | 값 | 여유 |
|---|---|---|---|
| 보정 추정 $\hat A$ | 9.67 + (27.87 − 35.51) | 2.03 | −7.38 |
| Chrono 실측 끔 | | 7.14 | −2.28 |
| 하네스 원시 | | 27.87 | +18.45 |

- **부호는 맞았고 크기는 약 3배 컸다.** 하네스 위상 민감도는 δ 0 → 0.03에서 −7.64 kN, Chrono는 −2.53 kN이다. 스윕 규칙은 Chrono 앵커에 하네스 위상 차를 그대로 더하므로 그만큼 과대했다. F_min 아래라는 판단은 맞았다.
- **하네스 원시가 20.7 kN 높은 이유**
  - 확인: 재접근 패턴이 다르다. 하네스 5회(FL 0.07, RR 0.47, RR 1.07, FL 1.57, RR 1.87), Chrono 7회(FL·RR을 세 번 번갈아, 뒤에 RL). 
  - 확인: 재접근이 갈라지기 전의 첫 골부터 다르다. FR 창 안 최소가 하네스 35.16 kN(δ 0), Chrono 16.6 kN이다. 패턴만의 문제가 아니다.
  - 확인: Chrono RL은 0.5~3 s에 7.1~162.8 kN으로 크게 흔들린다. 하네스 시계열은 저장하지 않아 직접 비교하지 못했다.
  - 추정: 하네스의 로킹 진폭이 작다. 토양·접촉 모델 차이(패드별 토양 스프링 대 SCM 격자)가 후보이고, 원인 분리는 안 했다. v4 "하네스가 연약 사건에서 낙관 쪽일 수 있음"과 같은 방향이다.
