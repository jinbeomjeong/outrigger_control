## 설계안과 지적

### 1. J7 A 적용 범위 (질문 1; 원칙 2·5)

**지적.** 지금 구현은 같은 항목을 비교에 따라 다르게 다룬다.
- C-J (i), A/A, G′에서는 기록이다.
- C-S(`v8 rules` 233행, 판정 4설정 184단위, 허용 E 0·N 0)와 C-J (ii)(232행, LSN 대 VBN L-a, `v5_criteria.md` 169행 "LS에서 J7 실패 0")에서는 실패다.

닫힌 목록의 근거는 비교와 상관없는 코드 성질이다: 기록 전용, 명령·상태 기계에 영향 없음, 줄당 1회. 그러니 그 근거가 비교에 따라 달라질 수 없다.

**통계적 영향**(해석식, 단위 사이 독립 가정)
- 두 비교는 모두 궤적이 완전히 갈라지는 짝이다. C-S는 VBN 감도 설정 대 V0이고, C-J (ii)는 LSN 센서 오차 설정 대 VBN이다. 판 8 A/A에서 위상 차이 1 ms만으로도 해시가 모두 달랐던 것과 같은 꼴이다.
- 그래서 목록 경고 플립율 p가 그대로 멈춤 확률로 간다.

| 단위 수 m | 비교 | p 0.05 % | 0.1 % | 0.2 % | 0.5 % | 1 % | 2.6 %(판 8 G′ A/A 값) |
|---|---|---|---|---|---|---|---|
| 100 | C-J (i) VBN | 4.9 % | 9.5 % | 18 % | 39 % | 63 % | 93 % |
| 184 | C-S 판정 4설정 | 8.8 % | 17 % | 31 % | 60 % | 84 % | 99.2 % |
| 288 | C-J (ii) LSN1~4 | 13 % | 25 % | 44 % | 76 % | 94 % | 99.95 % |
| 388 | C-J 전체 | 18 % | 32 % | 54 % | 86 % | 98 % | ≈ 100 % |

- census 위상 구성에서 실제 플립율은 모른다[추정]. 경고는 D1″가 크롤러 이탈 뒤 헤드 계단 후보를 처음 평가할 때만 난다. 그래서 사건 행이 아닌 줄에서는 기회가 없을 수 있다.
- 그렇다고 0이라고 둘 근거도 없다. 0.2 %만 돼도 C-J (ii)는 44 %의 확률로 거짓 멈춘다.
- 검출력 쪽 손실 φ(목록 경고에만 드러나는 해로운 효과의 몫)의 논리(지난 보고 1.2)도 비교마다 같다. 그래서 일부 비교에만 적용할 통계적 이유가 없다.
- 전례: C-S는 이미 "감도 J7 강성 경고 예외(단독 조건)"를 이어받고 있다(233행). 같은 꼴의 예외가 있는 셈이다.

**규칙 문면 권고(초안)**
> J7 닫힌 목록 {`WARN_D1_IMU_GYRO_MISSING`, `WARN_D1_IMU_INPUT_MISSING`}은 J7을 세는 모든 비교(C-J (i), C-J (ii) L-a의 J7, C-S 판정·기록 설정, 5단계 A/A, G′ 8단계, 그 밖에 J7을 쓰는 관문)에서 실패가 아니라 기록이다. 목록은 코드 성질(기록 전용, 명령·상태 기계 무영향, 줄당 최대 1회)로 정하고, 봉인 뒤 넓히지 않는다. 목록 밖 경고·FAULT는 그대로 J7 실패다. 비교마다 기록 칸 "목록 경고 플립 수(처리 쪽에만 있음)"를 낸다. 판 8 결과를 본 뒤 정한 것이므로 공개 항목이다.

- (b)를 고른다면 C-S·C-J (ii)의 V0 기준 줄에서 목록 경고 기회를 봉인 전에 세어 등록부에 적어야 한다. 위 표로 멈춤 확률도 함께 적는다.
- 도메인 확인: LS1~4나 감도 설정 가운데 IMU·자이로 입력을 빼는 설정이 있으면, `INPUT_MISSING`이 그 설정의 거의 모든 후보 줄에 나온다. 그때 (b)는 거의 확실히 멈춘다(위임 필요).

### 2. ITEM_GROUPS (질문 2)

지난 보고의 뜻은 기전별 분해였다. 세 갈래는 다음과 같다.
- **목록 경고**: φ와 플립 바닥을 볼 칸
- **FAULT**: D1 가짜 FAULT 계열
- **연속**: 문턱형 연속량. 위상 섭동으로 문턱 근처 줄이 갈리는 항목

| 군 | 구현(`impl_report` 1절) | 판단 | 권고 |
|---|---|---|---|
| 목록 경고 | J7 닫힌 목록, 실패든 기록이든 셈 | 뜻과 맞다 | 실패 방향(후보에만 있고 기준에는 없음)만 센다. **배타 칸 "목록 경고만 다른 짝"**(판 8 정의였다면 실패였을 짝)을 더한다. φ 추정과 판 8 대조에 쓰는 칸이다 |
| FAULT | J4 또는 J7 `FAULT_*` | **넓다.** J4는 "V0 ready인데 다른 단계로 끝남"이라 LEVEL 시간 제한 교착 같은 FAULT 아닌 종료도 들어간다 | FAULT = J7 새 `FAULT_*` 이름 또는 J4 중 후보 `final_phase`가 FAULT 계열인 경우. J4 나머지는 **"끝 상태(비 FAULT)"** 군으로 따로 둔다 |
| 연속 | J2·J5·J6·J8 | J3(첫 READY 한계·미도달)과 J10(이동 압력 ≤ 180 bar)이 빠졌다. J8(부호 전환 수)은 계수형이다 | 연속 = J2·J3·J5·J6·J10. J8은 "연속(계수)"로 표시하고 같은 군에 둔다 |
| 기타 | 나머지 | 목록 밖 J7 WARN이 여기에 묻힌다. 목록 경고를 내린 뒤 집합 차 바닥의 주 성분이 될 군이다 | **"J7 목록 밖 WARN"** 군을 따로 둔다. 기타 = J1 복합·J9·J11 |

- 군이 겹치므로 x를 군별로 더할 수 없다. 겹침 칸과 함께 우선순위 배타 귀속 칸도 낸다: FAULT ≻ J7 목록 밖 WARN ≻ 끝 상태(비 FAULT) ≻ 연속 ≻ 목록 경고만 ≻ 기타.
- 스모크 대조: ed8의 N 11 = 목록 8 + 3. 군 셈(목록 8, 연속 3, FAULT 3, 기타 3)은 "D1 FAULT 3짝이 연속·기타에도 걸린다"는 원인 분석과 맞는다. 판정에는 영향이 없다(기록 모드).

### 3. 5단계 구성: 저장 1356줄 + 같은 형상 7 job (질문 3; 원칙 1·3)

**R-2와의 차이.** 내 R-2는 C9에서 기준과 첫 후보 678 run을 새로 돌리는 안이었다. 이번 구현은 다음과 같다.
- R3a(끔): C9 끔으로 1356줄을 재생하고, 저장 C8 줄과 비트 동일한지 본다.
- R3b(켬): C9 켬으로 1356줄 + 7 job을 돌린다.
- R4: R3b 출력으로 ed9 A/A를 센다.

R3b가 쓰이는 짝 줄을 모두 C9 켬으로 다시 만든다. 그래서 같은 모델 경로라는 조건은 R-2보다 오히려 넓게(전 후보까지) 채워진다. 저장 줄이 하는 일은 정체성 증인뿐이다. 이 구성이면 충분하다. 다만 다음 다섯 조건이 붙는다.

1. **세는 줄은 R3b 줄만 쓴다.** 저장 C8 줄을 A/A 셈에 섞지 않는다. 비트 동일이 증명된 줄이라도 섞지 않는다(출처를 한 갈래로 두기 위해). 특히 S 8줄은 C8과 C9 켬이 다르다.
2. **층(E/N)과 기준 통과는 C9 켬 기준 줄 V0(o)로 다시 정한다.**
   - 기준 실패 3슬롯은 C-m으로 기준 줄이 바뀌면 기준 통과가 될 수 있다. 그러면 n이 바뀐다(control P9-AA: n_AA,N 310~313).
   - FAULT 줄은 재접근이 없어 저장 줄에서는 구조상 N이다. 켬 줄에서는 E가 될 수 있다.
   - G′ 8단계 처리 단위의 층도 같은 C9 켬 V0(o)에서 정한다(규칙 269행 "층은 처리 전 공변량").
3. **새 7 job은 끔에서도 돌린다**(R3a에 7 run 추가, 약 1분).
   - 저장 대응이 없어서 R3a로는 끔 정체성을, P9-D1-2로는 "켬은 D1_step 줄만 바꾼다"를 확인할 수 없다.
   - 끔·켬 7쌍을 `compare_identity`로 대조한다. 기준은 끔에서 D1_step이 없으면 비트 동일이다.
4. **처리 팔(VBN)도 C-m 켬이어야 하고, 줄마다 스위치 상태를 정체성으로 확인한다.**
   - VBN이 끔이면 처리 팔에만 가짜 FAULT 창(FR 빠른 램프 위상의 약 7 %)이 남는다. 이것은 A/A가 볼 수 없는 처리율 q다(지난 보고 3.2: q ≈ 0.23~0.53 %, x 0·k 3에서 거짓 실패 0.4~11.8 %).
   - 그래서 확인 필요 1의 스위치 경로는 줄에 상태가 남는 (가) 태그 접미사가 통계적으로 안전하다. (나)는 켬·끔 줄이 같은 job key라 섞일 위험을 python이 이미 적었다.
5. **R3b가 예측과 어긋나면 봉인 전에 멈춘다.** 두 경우다.
   - differing이 S 밖에 생김(P9-D1-2 위반)
   - S 줄이 바뀌지 않음(`allowed_unchanged` > 0, P9-D1-3 위반)

   이 상태로 센 x는 k 봉인에 쓰지 않는다. 숫자는 맞게 나오지만 기전 예측이 틀린 경로이기 때문이다.

- 덧붙임: census V0 줄(main 100줄, 격자 768 run)은 S = 0이다(R1).
  - C-m은 C0가 설명하지 못한 경우에만 판정을 바꾼다(부분집합 성질). 그래서 이 줄들은 켬에서 비트 동일하다고 연역된다.
  - 실행 증거는 R3b의 S 밖 1348줄 불변과 단위 시험(스위치 켬, D1_step 없는 각본)이다. census 줄 자체를 켬으로 다시 돌린 증거는 없다. 이 사실을 공개 문구에 적는다.
- 5단계 해시 재생(봉인 뒤)은 R3b와 같은 커밋·인터프리터 호출 방식에서 같은 줄을 재생한다(python 확인 필요 6). 다르면 구현 결함으로 멈춘다.

### 4. 같은 해시 짝 제외·재시도 없음 (질문 4)

- **제외가 맞다.**
  - 처리 짝 VBN(o) 대 V0(o)는 제어기가 달라 늘 갈라진다(c ≈ 1).
  - 같은 해시 A/A 짝은 결정적 통과일 뿐 바닥 정보가 없다. 넣으면 x/n_AA가 낮아지고, k도 낮아져 거짓 실패가 는다.
- **재시도 없음도 맞다.**
  - 해시 동일은 V0끼리의 성질이라 결과 선택은 아니다. 하지만 위상에 둔감한 슬롯은 다음 위상에서도 같을 가능성이 크고(메모리 함정 16), 돌리지 않은 줄이 필요해진다.
