## 2-1. 12b 등급 전이 기록의 L1 기준(6.3.7 마지막 문단, 6.3.9)
- 사례 원본 `h8_noise_VB.json`의 L1 줄은 기준으로 쓰지 않는다. 그 줄은 VB 설정이고 `rod_model` = `dyn_map`이라서, VBK·VBK0(`plant_truth`) 줄과 짝이 생기지 않는다. 판 4a-8 4.1과 같은 이유다.
- L1 기준은 판 5 실행 커밋에서 새로 돌린 L1 실행이다. 판 4a-8 4.1 선례대로 각 팔은 자기 설정의 L1을 쓴다.
  - VBK0 팔: VBJ0 설정의 L1
  - VBK 팔: VBJ 설정의 L1(VBK와 같은 옵션, 고장 계획 없음)
  - 두 실행 모두 `R79_ROD_MODEL=plant_truth`로 돌린다.
- L1 키: 12b 사례 167개에서 서로 다른 (harness, inner)마다 `L1|s0|<harness>|<case_index>|<inner>`를 하나씩 만든다. 순서는 사례 원본에서 처음 나온 순서다.
- L1 키 파일과 두 L1 실행 파일의 sha256은 `FIXED_INPUTS_<판 5 실행 커밋>`에 넣는다. `grade-judge`는 그 sha를 대조한다.
- 실행 위치: 실행 전 준비 단계에서 돌린다(2-6 순서의 `l1keys` → `step_l1ref`). 12b·c 건식 출력보다 앞선다. 걸리는 시간은 수 분이다(가정).
- **L1 기준은 12b·c 건식 출력이 하나라도 생긴 뒤에는 다시 만들지 않는다.** L1 기준 실행의 재시도는 4a-5 5절을 따르고, 쓰는 시도는 `l1ref.done`이 가리키는 시도다(감사 경고 2).
- 등급 전이는 판정이 아니라 기록이다(6.3.7).
  - 기록에 `ungraded_pairs`를 함께 공개한다.
  - 기회 짝 가운데 `ungraded`가 1개 이상이면 그 원인(짝 L1 없음 등)도 공개한다.
  - **등급 전이 입력(L1 기준, `grade-judge` 파일)에 결함이 있으면 등급 전이 기록을 "계산 안 됨"과 그 사유로 공개할 뿐, 12b 판정 상태와 종료 코드는 바꾸지 않는다**(감사 F-1). 결함의 예: L1 기준의 오류 줄, 줄 수와 키 수 불일치, `rod_model`·설정 불일치, `grade-judge` 파일 sha 불일치. 이 결함으로 12b가 판정 불가(종료 2)가 되거나, 실패(종료 1)가 판정 불가로 가려져서는 안 된다.
  - `grade-judge`의 도구 오류(종료 3)도 같은 결함으로 본다. 단계를 멈추지 않고 12b 판정을 끝까지 돌린다. 등급 전이 기록에는 `computed: false`와 사유 "grade-judge 종료 3"을 남긴다.
