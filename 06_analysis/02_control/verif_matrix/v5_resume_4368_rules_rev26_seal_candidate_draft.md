## 0. 공개 (결과를 본 뒤의 개정)
- **결과를 본 뒤의 재판정이다.** 대상 결함은 436.8 판정 후 감사(B-2)와 판정서 작성 중에 결과를 본 뒤 찾았다.

## 2. R26-2 값 대응표 (결과 전 고정)

| `ind_las` 기존 필드 상태 | `status` | `markers` |
|---|---|---|
| `record_state` "기록", `adapter_defect` 거짓, 판독 불가 0 | `"기록 완료"` | `[]` |
| `adapter_defect` 참 | `"기록 불완전"` | `["IND_LAS:adapter_defect"]` |
| 판독 불가 n > 0(`adapter_defect` 거짓) | `"기록 불완전"` | `["IND_LAS:판독 불가 <n>"]`(n은 정수 그대로) |
| `adapter_defect` 참이고 판독 불가 n > 0 | `"기록 불완전"` | `["IND_LAS:adapter_defect", "IND_LAS:판독 불가 <n>"]`(이 순서) |
| 그 밖(`record_state`가 "기록"이 아니거나 키 결측) | `"기록 불완전"` | `["IND_LAS:기록 상태 미정"]` |

- `status`는 등급 대조 표 1.1의 낱말만 쓴다(36~46행, H-7 행 108행). IND_LAS `status`는 기록 열 낱말이라 H-4 묶음 등급 낱말에 들어가지 않는다.
- **표지 문자열 꼴의 근거**
  - 비교기 `compare_r4.py`의 `bundle_markers`는 경로 1 `r4_lists.json bundles.{b}.markers`와 경로 2 `harness.json bundles.{b}.gates`만 읽는다(81·132행). 대조하는 것은 RD-8 표지 `"J-P3 입력 형식(RD-8)"`의 유무뿐이다(291·802~812·1094~1099행). `ind_las.json`은 비교기가 읽지 않는다.
  - 등급 대조 표 1.2 2는 표지 이름을 RD-4 이름으로 옮겨 비교한다. RD-4(R4 공통 블록 54행)는 표지 이름과 등급·묶음 이름이 섞이지 않게 하라고 한다. 그래서 표지 이름에 1.1 등급 낱말(`판정 불가`)을 쓰지 않고, 열 이름 접두 `IND_LAS:` + 사유로 쓴다.
  - IND_LAS는 경로 1에만 있는 기록 열이다(등급 대조 표 105행 경로 2 쪽에 IND_LAS 없음). 그래서 이 표지는 H-12와 같은 "한 경로 기록"(115행)으로 다루고, 1.2 2 집합 비교에 넣지 않는다.
- `markers`가 비어 있지 않으면 IND_LAS는 `기록 불완전`이고, H-4는 H-3과 같은 규칙으로 `판정 불가`다(105행).
- 436.8 데이터가 지나는 칸은 첫 행이다(작성자가 안다, 0절). 그 칸의 값은 위에 정했다.

## 3. 구현 조건
- 보완마다 다음을 구현 전 문안(봉인본 부록)에 적는다.
  - 근거 정의 문장(파일:행)
  - 값 대응표(R26-2, 2절)
  - 동치 대안 확인
- **동치 대안 확인은 판정 도구가 아니라 식별자만 읽는 점검으로 한다**(예: U-3 키의 연구 간 중복 0 — 1,114 키, 중복 0).
- 작성자: 두 보완(R26-1 경로 2, R26-2 경로 1)은 **436.8 H-3·H-4 출력과 판정 후 감사의 해당 줄을 읽지 않은 새 인스턴스**가 한다. 서로 다른 경로의 코드·출력을 열지 않는다. R26-3은 두 작성자가 1절 정의 문장만으로 각자 맞춘다.
- **보완 한 번 = 도구 커밋 하나.**
  - 개발 시험은 합성 고정물로만 한다.
  - **판정 도구는 봉인 뒤 5단계(재판정) 실행 전에 436.8 저장 결과에 돌리지 않는다(어느 묶음이든).**
  - (d)의 불변 diff는 5단계 1회 실행 출력과 원 출력 `judge_932f1fb/`를 비교해 확인한다.
  - 5단계는 메인이 1회만 하고, 명령·시각·sha를 기록한다. 그 전에 실행한 적이 있으면 공개하고 출력을 보존한다.
