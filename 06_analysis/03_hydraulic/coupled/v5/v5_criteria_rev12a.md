### 2.2 대기 정책은 결과 비트를 바꾸지 않는다고 본다

| 근거 | 내용 |
|---|---|
| 실측 | cad-expert, J1 B 정착 1.5 s(`run_S9 machine`, `--threads 4`): ACTIVE ↔ PASSIVE의 `series.npz` 18배열과 `result.json`(경로·이름 키 제외)이 비트 동일(`omp_cmp.json` `identical: true`, `result_json_sha256_stripped` 같음) |
| 기구 | `OMP_WAIT_POLICY`는 병렬 구역 사이에서 쉬는 스레드가 회전 대기하는지 잠드는지만 정한다. 작업 분할과 병합 순서는 정하지 않는다. SCM의 비트 의존은 스레드 수에 따른 hit 맵 병합 순서에서 온다(decision_log 449, `SCMTerrain.cpp` 1211~1290). 그래서 스레드 수는 실행 정체성이고, 대기 정책은 타이밍만 바꾼다 |
| 타이밍 무관 재현 | 같은 `--threads`면 날짜·동시 부하가 다른 실행끼리도 비트가 같았다. 예: J1·G1 열린 루프 V0(2026-11-08)과 v4(2026-10-26)의 `series.npz` 18배열 최대 절대차 0(`v5_paper_runs_judgement.md` 1.1절). 결과가 타이밍에 의존한다면 이런 재현은 성립하지 않는다. 대기 정책은 타이밍 변수다 |

### 2.3 한계

- 실측은 ACTIVE ↔ PASSIVE다. **미설정 ↔ PASSIVE를 직접 잰 적은 없다.** MSVC vcomp의 미설정 기본 거동이 ACTIVE·PASSIVE 중 어느 쪽과 같은지는 확인하지 않았다. 2.2의 기구 논거(대기 정책은 타이밍만 바꾼다)에 기댄다.
- 실측 구간은 정착 1.5 s다. LEVEL 120 s 전체와 run_S8C(L2b NSC)는 재지 않았다.
- 그래서 4절 플랜트 선행 검사를 행마다 둔다. 동치가 틀렸다면 제어기 명령이 달라지기 전에 플랜트가 먼저 갈라진다. 이 검사는 그 경우를 "작동"으로 잘못 적지 않게 막는다.
- 이 비교는 기록이다(개정 12 2.2). 동치가 틀려도 판정은 바뀌지 않는다. 잘못될 수 있는 것은 "LAS-b 미작동·③ 미작동 확인" 문구뿐이고, 4절이 그것을 막는다.

### 2.4 고르지 않은 것

| 안 | 고르지 않은 이유 |

| (나) 엄격 유지, 재실행을 OMP 미설정으로 | SCM 실행 규칙(사용자 결정 2026-11-08, PASSIVE)과 맞지 않는다. 재실행 행은 판정에 쓰는 결과다. 기록 하나를 위해 판정 행의 실행 조건을 바꾸는 것은 순서가 거꾸로다. 또 저장 쪽 미설정도 추정이라 엄격하게 맞췄다는 보장이 없다 |
| (나) 엄격 유지, 전부 비교 불가 | 토양 행 기록이 모두 사라진다. 도구는 비교 행이 0이면 종료 코드 2를 낸다. 다만 run_S8C 행은 양쪽 모두 `unrecorded`라 "같은 값"으로 비교된다. 실제로는 재실행 쪽 자식 env가 `00b86aa` 뒤 PASSIVE다. 그래서 엄격 규칙은 같은 문자열이라는 이유로 다른 조건을 같게 보는 구멍이 있다 |

## 3. `OMP_WAIT_POLICY` 기록 규칙

- 행마다 저장·재실행 양쪽에 다음을 적는다(판정·비교 조건에는 쓰지 않는다).
  - `value`: `result.json` `placement.omp_wait_policy`, 없으면 `case.json` `runner.placement.omp_wait_policy`, 없으면 재실행 batch 행 필드 `omp_wait_policy`(있을 때), 모두 없으면 `unrecorded`
  - `source`: 위 출처 이름
- 저장 34행과 짝 저장 행(P-1·P-2·P-3)의 `unrecorded`는 2.1에 따라 "미설정(추정)"으로 읽는다. 판정서에 이 읽기를 적는다.
- 재실행 행에 `PASSIVE`가 아닌 값이 기록되면(예: 명시 ACTIVE) 그대로 기록한다. 비교 조건은 바뀌지 않는다.

## 4. 플랜트 선행 검사

해시 비교 조건(같은 `--threads`, 둘 다 P코어)을 만족한 행에만 적용한다.

| 항목 | 정의 |
|---|---|
| 플랜트 배열 | S9 행 `step_series.npz`(시각 `t_s`): `F_cyl_N`, `s_motor_m`, `roll_pitch_deg`, `z_origin_m`, `scm_pad_normal_N`, `scm_crawler_normal_N`. run_S8C 행 `pads.npz`(시각 `t`): `F_cyl`, `s_motor`, `body_quat_wxyz`, `N`, `crawler_normal_N` |
| $t_p$ | 위 배열 중 하나라도 비트 단위로 다른 첫 표본의 시각(양쪽 공통 길이 안, 시각 배열도 비트 비교). 공통 길이가 모두 같고 길이만 다르면 짧은 쪽 끝 다음 표본 시각. 모두 같으면 $+\infty$ |
| $t_c$ | 명령 배열(개정 12 2.2 검사 1)의 첫 다른 주기 시각(재실행 쪽 시각). 명령이 모두 같으면 $+\infty$ |
| 플랜트 선행 | $t_p < t_c - 10^{-6}$ s. 명령이 모두 같은데 플랜트가 다른 경우도 여기에 든다($t_c = +\infty$) |
| 결과 | 플랜트 선행이면 "조건 다름(플랜트 선행), 해시 비교 없음"으로 적는다. $t_p$, $t_c$, 처음 다른 배열 이름을 함께 적는다. 명령이 달라진 행에서 플랜트 선행이 아니면 개정 12대로 "작동"이다 |
| 배열 없음 | 위 배열이나 키가 한쪽에라도 없으면 "조건 다름(플랜트 배열 없음), 해시 비교 없음" |

- 근거: 재실행이 바꾼 것은 제어기(태그·LAS-b·③)뿐이다(개정 12 2.1, 플랜트·사례·사건·시드 인자 같음). 제어기 변경은 명령을 거쳐서만 플랜트에 닿는다. 훅 입력은 다음 스텝부터 반영된다(CLAUDE.md 1스텝 지연 규약). 그래서 $t_c$ 전의 플랜트 차이는 제어기 밖 원인이다. 대기 정책, 플랜트 코드 변경, 비결정성이 그런 원인이다.
- 플랜트 선행 행이 하나라도 있으면 메인 세션에 보고한다. cad-expert가 그 행을 `OMP_WAIT_POLICY` 미설정 / PASSIVE로 짧게(정착 구간) 다시 돌려 원인을 확인한다. 판정은 멈추지 않는다(기록이므로).
